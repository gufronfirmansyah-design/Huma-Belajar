01 · Membuat database Supabase

SQL adalah instruksi untuk menyiapkan tabel dan aturan akses database. Salin isi file, bukan nama file. Pilih satu jalur di bawah sesuai kondisi proyek.

A. Membuat proyek baru

  1. Buka Supabase Dashboard dan masuk dengan akun pemilik aplikasi. Akun dashboard ini berbeda dari akun siswa.
  2. Klik New project.
  3. Pilih organisasi Anda. Bila diminta membuat organisasi, ikuti formulir yang tampil.
  4. Isi Project name, misalnya HUMA BELAJAR.
  5. Buat Database password yang kuat dan simpan secara pribadi. Ini bukan password admin aplikasi.
  6. Pilih region yang tersedia dan sesuai lokasi pengguna. Periksa biaya paket di layar sebelum menyetujui.
  7. Klik Create new project. Tunggu hingga proyek selesai disiapkan.
  8. Klik nama proyek untuk masuk ke dashboard proyek.

B. Instalasi baru — SATU FILE

Gunakan hanya ketika belum ada tabel public.profiles. Tidak perlu menjalankan file 01 sampai 06 satu per satu.

  1. Di laptop, buka 04-BACKEND/00-INSTALASI-BARU.sql dengan Notepad.
  2. Tekan Ctrl+A, lalu Ctrl+C.
  3. Di dashboard Supabase, klik SQL Editor pada menu kiri.
  4. Klik New query atau tombol + untuk membuka query kosong.
  5. Klik area editor lalu Ctrl+V.
  6. Pastikan role eksekusi adalah postgres (pemilik database), kemudian klik Run.
  7. Tunggu hasil. Yang diharapkan: Success. No rows returned atau hasil sukses sejenis.
  8. Buka query baru dan jalankan: select public.public_status();
  9. Pastikan hasil menyebut schema_version: 1.5.0.
  10. Buka Table Editor → public. Pastikan ada profiles, records, schools, account_handles, dan tabel lain.

Installer berjalan dalam satu transaksi: seluruh pemasangan berhasil bersama, atau dibatalkan jika ada error. Installer menolak menimpa database yang sudah mempunyai profiles.

Checkpoint: versi database 1.5.0. Lanjut kategori 02, jangan langsung mencoba login sebelum layanan accounts dipasang.

C. Upgrade database lama

  1. Cadangkan database dan berkas sesuai kategori 07.
  2. Di SQL Editor, jalankan select public.public_status();.
  3. Jika sudah 1.4.0, jalankan hanya 06-upgrade-1.5.sql.
  4. Jika 1.3.0, jalankan 05-upgrade-1.4.sql, kemudian 06-upgrade-1.5.sql.
  5. Jika 1.2.0, jalankan 04-upgrade-1.3.sql, 05-upgrade-1.4.sql, kemudian 06-upgrade-1.5.sql.
  6. Jika 1.1.0, jalankan 02-upgrade-1.1.sql, 03-upgrade-1.2.sql, 04-upgrade-1.3.sql, 05-upgrade-1.4.sql, lalu 06-upgrade-1.5.sql, masing-masing tunggu sukses.
  7. Jika public_status tidak ditemukan tetapi tabel sudah ada, hentikan dulu dan periksa versi/skema. Jangan memaksa installer baru.
  8. Periksa ulang public_status. Target 1.5.0.
  9. Akun Google lama memerlukan username. UUID akun, progres, dan penugasan tetap dipertahankan; lihat kategori 02 bagian pemindahan akun lama.

D. Error profiles tidak ada

Pesan relation public.profiles does not exist berarti upgrade dijalankan sebelum tabel dasar tersedia.

  1. Klik Table Editor, pilih schema public.
  2. Bila belum ada tabel aplikasi, jalankan 00-INSTALASI-BARU.sql.
  3. Bila sudah ada sebagian tabel tetapi profiles tidak ada, jangan menghapus tabel sembarangan. Salin pesan error dan periksa proyek yang dipilih.
  4. Untuk benar-benar memulai dari awal, boleh membuat proyek baru yang kosong. Biarkan proyek lama sebagai cadangan sampai hasil baru diperiksa.

E. Yang tidak boleh dipublikasikan

Database password, service_role/secret key, daftar password siswa, dan data pribadi tidak masuk GitHub. Konfigurasi website hanya memakai Project URL dan publishable key/anon key.
