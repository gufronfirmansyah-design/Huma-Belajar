02 · Username, password, dan impor akun

Google Console tidak digunakan pada versi 1.5. Anda tetap masuk ke dashboard Supabase memakai akun pemilik proyek seperti biasa; siswa dan guru masuk di website dengan username.

A. Atur layanan login Supabase

  1. Buka proyek Supabase.
  2. Klik Authentication di menu kiri.
  3. Buka Sign In / Providers (pada tampilan lain bernama Providers).
  4. Buka Email, aktifkan Enable Email provider / email-password login, lalu Save.
  5. Di pengaturan pendaftaran, matikan Allow new users to sign up. Pembuatan akun dilakukan oleh fungsi accounts memakai Admin API, sehingga siswa tetap dapat mendaftar melalui formulir HUMA BELAJAR.
  6. Matikan Anonymous sign-ins jika aktif.
  7. Buka provider Google, nonaktifkan, lalu simpan. OAuth Client ID/Secret tidak diperlukan.
  8. Jangan menonaktifkan provider Email. Meskipun siswa mengetik username, Supabase Auth tetap memakai identitas email internal di belakang layar.

Alamat seperti username@accounts.huma.invalid adalah identitas internal, bukan kotak email. Tidak ada pengiriman email konfirmasi atau reset ke alamat itu. Pemulihan password melalui admin pusat setelah identitas pemilik diverifikasi.

B. Pasang fungsi accounts

Edge Function adalah layanan kecil di server yang membuat akun dan memeriksa hak admin. File ini tidak diunggah ke GitHub Pages.

  1. Pada menu kiri proyek, klik Edge Functions.
  2. Klik Deploy a new function → Via Editor / Open Editor.
  3. Isi nama fungsi tepat accounts.
  4. Pada file index.ts, hapus kode contoh.
  5. Di laptop, buka 04-BACKEND/functions/accounts/index.ts dengan Notepad, Ctrl+A, Ctrl+C; tempel seluruhnya ke index.ts di dashboard.
  6. Di daftar file editor, klik Add file / tombol +, buat file handler.js di folder yang sama dengan index.ts.
  7. Buka 04-BACKEND/functions/accounts/handler.js di laptop. Salin seluruh isi dan tempel ke handler.js di dashboard.
  8. Klik Deploy function / Deploy updates. Tunggu status berhasil.
  9. Buka halaman fungsi accounts → Details / pengaturan fungsi. Cari Verify JWT with legacy secret, lalu nonaktifkan dan simpan. Formulir daftar/login harus bisa dipanggil sebelum pengguna punya sesi.
  10. Penonaktifan pemeriksaan gateway bukan pemberian hak admin: fungsi tetap memverifikasi token pengguna sendiri untuk membuat/reset akun, dan hanya admin pusat yang diizinkan.
  11. Rahasia SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY tersedia sebagai variabel bawaan Edge Functions. Jangan menempelkannya ke HTML atau konfigurasi publik.
  12. Jika editor belum menyediakan penambahan file, buka editor penuh fungsi. Kedua file harus terlihat berdampingan sebelum deploy; jangan menghapus baris import handler.js.

Checkpoint: fungsi accounts terlihat di daftar, deploy berhasil. Kategori 03 menyediakan tombol Periksa koneksi untuk memeriksa respons dasarnya.

C. Siswa mendaftar sendiri

Setelah admin membuat sekolah, kelas, dan kode (kategori 04):

  1. Siswa membuka alamat website produksi.
  2. Klik Belum punya akun? Daftar siswa.
  3. Isi Username, Nama lengkap, pilih Sekolah.
  4. Masukkan Kode undangan kelas dari sekolah.
  5. Isi password minimal 12 karakter, lalu ulangi.
  6. Klik Buat akun siswa.
  7. Bila berhasil, siswa masuk ke kelas yang sesuai kode.
  8. Jika gagal, baca pesan di bawah formulir. Isian tidak dihapus; perbaiki lalu kirim lagi.

Username unik di seluruh aplikasi, 3–32 karakter, menggunakan huruf kecil, angka, titik, garis bawah atau minus. Karakter pertama huruf/angka. Jangan gunakan dua titik berurutan atau titik di akhir. Awalan sekolah membantu, misalnya sekolahx.andi01. Ini contoh penamaan, bukan akun yang sudah dibuat.

Pendaftar tidak dapat memilih peran admin/guru. Kode undangan membuka keanggotaan siswa saja.

D. Admin membuat satu akun

  1. Masuk sebagai admin pusat, buka Akun pengguna.
  2. Periksa sekolah aktif di bagian atas.
  3. Pilih Kelas tujuan untuk akun siswa. Untuk calon guru/pengelola pilih Tanpa kelas.
  4. Isi nama dan username, klik Buat akun.
  5. Pada Hasil pembuatan / reset, salin password sementara atau klik Unduh hasil privat (CSV).
  6. Bagikan hanya kepada pemilik akun. Jangan masukkan file hasil ke GitHub.
  7. Pengguna masuk dan mengganti password sementara dahulu.
  8. Untuk guru/admin sekolah, lanjutkan pemberian peran dan penugasan pada kategori 04. Membuat akun saja tidak memberi hak pengelola.

E. Impor banyak siswa dari Excel

  1. Buka Akun pengguna → Unduh template Excel.
  2. Buka Template-Akun-Siswa.xlsx di Excel.
  3. Klik lembar AKUN. Baca lembar PETUNJUK bila perlu.
  4. Jangan ubah judul kolom nama dan username.
  5. Ganti/hapus baris contoh. Isi satu siswa per baris, maksimal 100 siswa per unggahan.
  6. Simpan sebagai Excel Workbook (.xlsx), tanpa formula, macro, gambar, atau kolom tambahan.
  7. Kembali ke aplikasi. Pilih sekolah aktif dan kelas tujuan. Satu file untuk satu kelas.
  8. Pada File XLSX, klik Choose file / Pilih file dan pilih template yang sudah diisi.
  9. Klik Periksa & pratinjau. Belum ada akun yang dibuat pada tahap ini.
  10. Periksa nama, username, dan kelas.
  11. Klik Buat akun dari pratinjau, baca konfirmasi lalu setujui.
  12. Tunggu setiap baris selesai. Jangan menutup tab.
  13. Periksa hasil setiap siswa. Username yang sudah ada dilewati dan tidak dipindahkan kelasnya.
  14. Klik Unduh hasil privat (CSV) sebelum menutup halaman. Hasil berisi password sementara; simpan di lokasi pribadi.
  15. Bagikan password masing-masing secara pribadi. Jangan membagikan seluruh daftar ke grup kelas.
  16. Klik Bersihkan hasil dari layar setelah selesai.

Jika beberapa baris gagal, tombol yang sama mencoba baris yang belum berhasil. Jika browser terlanjur tertutup, unggah ulang file: akun yang sudah ada dilewati. Password lama tidak ditampilkan lagi; gunakan reset untuk akun yang kehilangan password sementara. Tidak ada penyimpanan daftar password di browser atau tabel aplikasi.

Batas 100 baris / 2 MB dan pembatasan permintaan adalah batas teknis awal, bukan kuota berbayar. Untuk banyak sekolah, lakukan bertahap dan pantau kapasitas proyek Supabase.

F. Lupa password dan pemindahan akun Google

Reset oleh admin pusat:

  1. Verifikasi bahwa pemohon benar pemilik akun melalui sekolah.
  2. Buka Akun pengguna → Muat daftar akun.
  3. Cari nama/username, klik Reset password, lalu konfirmasi.
  4. Bagikan password sementara yang baru secara pribadi.
  5. Pengguna masuk dan menggantinya. Admin tidak melihat password lama.
  6. Pengguna yang mengetahui password lamanya bisa membuka Profil → Ganti password.

Akun Google lama:

  1. Jangan hapus user di Authentication. Penghapusan dapat memutus hubungan progres.
  2. Setelah admin pusat lama dipindahkan oleh pemilik proyek, buka Akun pengguna → Muat daftar akun.
  3. Akun tanpa username memiliki tombol Buat username. Klik, isi username unik, konfirmasi.
  4. Muat daftar lagi, lalu klik Reset password untuk memberikan password sementara.
  5. UUID, peran, dan progres tetap menggunakan akun yang sama.

Memindahkan admin pusat lama pertama (oleh pemilik proyek saja):

  1. Di Authentication → Users, cari email admin pusat lama. Salin User UID.
  2. Pastikan UID tersebut memang admin pusat pada public.profiles (central_admin=true). Jangan memilih berdasarkan nama saja.
  3. Di SQL Editor jalankan contoh berikut dengan mengganti UUID, bukan email/password:
insert into public.account_handles(username,user_id,must_change)
select 'adminutama',id,true from public.profiles
where id='GANTI-DENGAN-UUID-ADMIN'::uuid and central_admin and active;
  1. Di Authentication → Users, buka user yang sama, pilih Update user / Change password, tetapkan password sementara secara pribadi. Jika dashboard Anda tidak menyediakan ubah password, jangan membuat ulang user; gunakan Admin API melalui lingkungan server milik pemilik proyek.
  2. Masuk sebagai adminutama, ganti password sementara, lalu pindahkan akun lain lewat aplikasi.
  3. Jangan menjalankan 07-ADMIN-PERTAMA.sql pada database yang sudah punya admin pusat berbeda.

G. Bila perubahan password terputus

Perubahan password melibatkan layanan Auth dan tabel aplikasi. Jika server berhenti di tengah proses, akun dikunci untuk mencegah status seolah berhasil.

  1. Coba masuk kembali. Bila muncul “perubahan password lain belum selesai”, hubungi pemilik proyek.
  2. Pemilik proyek memeriksa UID akun dan memastikan tidak ada permintaan yang masih berjalan.
  3. Melalui SQL Editor, jalankan update public.account_handles set password_job=null, must_change=true where user_id='UUID-YANG-BENAR'::uuid;.
  4. Admin pusat kemudian melakukan Reset password lagi. Jangan mengubah must_change menjadi false secara manual.
  5. Jika akun yang terkunci adalah admin satu-satunya, ubah password melalui dashboard Auth/Admin API, kemudian masuk dan selesaikan ganti password. Simpan pemulihan proyek untuk pemilik yang berwenang.

Referensi layanan

Supabase password authentication dan Admin createUser, serta pemeriksaan sesi. Menu dashboard bisa berubah; selalu pastikan proyek dan nama fungsi benar.
