07 · GitHub, perubahan, dan cadangan

A. Mengunggah website dari awal

  1. Simpan salinan repository lama sebelum mengganti isi.
  2. Buka folder 01-WEBSITE-SIAP-UPLOAD di laptop.
  3. Buka repository GitHub → Code → Add file → Upload files.
  4. Seret seluruh isi folder siap unggah, termasuk subfolder. Jangan mengunggah ZIP atau folder pembungkus.
  5. Periksa index.html, config.public.json, folder lib, modules, vendor, dan panduan berada pada tingkat yang benar.
  6. Klik Commit changes.
  7. Buka Settings → Pages. Untuk metode branch, pilih Deploy from a branch, pilih branch yang berisi file (misalnya main), pilih /(root) jika index.html ada di akar, lalu Save.
  8. Tunggu penerbitan. Buka alamat website yang ditampilkan halaman Pages; alamat ini berbeda dari alamat repository.
  9. Muat ulang Ctrl+F5, buka pengaturan/panduan, lalu uji login jika konfigurasi sudah production.

Jika sebelumnya memakai GitHub Actions, jangan mengganti metode penerbitan tanpa memeriksa workflow yang sudah ada. GitHub Pages perlu dinilai kesesuaiannya sebelum layanan komersial; kompatibilitas file statis tidak berarti semua penggunaan bisnis diizinkan. Ketentuan penggunaan Pages.

B. Mengubah aplikasi atau hanya menambah konten

  • Menambah soal/materi: melalui aplikasi setelah database terhubung; tidak perlu mengedit GitHub.
  • Mengubah fitur/tampilan: edit file terkait di 02-KODE-SUMBER, lalu jalankan PERBARUI-WEBSITE.bat.
  • Unggah hasil 01-WEBSITE-SIAP-UPLOAD, bukan file sumber yang belum diperbarui.
  • Jika sudah pernah menandai versi terbit, baca 07-UPDATE-TERAKHIR/BACA-DULU.md untuk perubahan saja. Jangan menandai sudah diunggah sebelum benar-benar selesai diperiksa.
  • Jika BAT gagal karena folder dikunci Windows: tutup penampil ZIP, editor, atau terminal yang sedang memakai folder hasil, lalu coba lagi. Jangan menghapus database atau memaksa hapus folder.

C. Cadangan sebelum pembaruan database

  1. Catat versi website dari VERSION.txt dan versi database dari public_status().
  2. Simpan paket aplikasi dan config publik yang benar di lokasi cadangan.
  3. Buka Supabase → pengaturan Database / Backups sesuai paket proyek. Periksa cadangan yang benar-benar tersedia, tanggalnya, dan ketentuan pemulihan. Jangan menganggap setiap paket memiliki cadangan otomatis.
  4. Jika fasilitas cadangan lengkap tidak tersedia, minta bantuan menyiapkan ekspor PostgreSQL lengkap dan uji pemulihan. Ekspor CSV dari Table Editor bukan pengganti cadangan database lengkap.
  5. Cadangkan berkas Storage dan sumber materi Drive secara terpisah; cadangan database saja tidak menjamin isi file Storage ikut tersimpan.
  6. Pulihkan dahulu ke proyek uji dan periksa login, relasi kelas, materi, gambar, serta hasil latihan sebelum menyatakan cadangan dapat dipakai.

Pembaruan yang hanya mengubah panduan/rumus tidak memerlukan SQL baru. Migrasi lama tidak dijalankan ulang hanya karena website diganti.

D. Jika perlu kembali ke versi lama

Hentikan penulisan, cadangkan kondisi terbaru, dan uji pasangan versi website/database yang sesuai. Jangan memulihkan database produksi atau menimpa data siswa hanya untuk mencoba. Data yang masuk setelah cadangan harus diperhitungkan. Paket ini belum menyediakan tombol pemulihan produksi otomatis.
